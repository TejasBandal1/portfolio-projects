# SMS Spam Detector

Classify an SMS message as spam or ham. The project compares a word/character TF-IDF + Multinomial Naive Bayes baseline with TF-IDF + class-weighted Logistic Regression. The app shows the class and a calibrated-style model probability (not a guarantee), while the report includes precision, recall, F1, ROC-AUC, and a confusion matrix.

## Data

UCI SMS Spam Collection, 5,574 labeled messages: [dataset page](https://archive.ics.uci.edu/dataset/228/sms+spam+collection). The downloader retrieves the original ZIP and extracts only the tab-separated `SMSSpamCollection` file. UCI terms apply; the dataset is downloaded locally and is not committed.

## Run

```powershell
pip install -r requirements.txt
python train.py
streamlit run app.py
```

The first run downloads the dataset. The fixed stratified holdout is 20%; all vocabulary fitting happens inside the training pipeline to avoid test leakage. Outputs go to `artifacts/` and `reports/`.

## What to inspect

Compare the two models in `reports/metrics.json`, especially spam recall and precision. Inspect `reports/top_terms.csv` for influential class terms and the saved confusion matrix. Thresholds can be tuned for a product's cost of missed spam versus false alarms.

## Limitations

This small, older English SMS dataset does not represent modern messaging, other languages, or adversarial spam. Text indicators can be misleading, so do not treat predictions as proof that a message is safe or malicious.

## Measured result

Evaluated once on the fixed stratified 20% holdout (seed 42; 1,115 messages). Logistic Regression improves spam recall over Naive Bayes while keeping precision high:

| Model | Accuracy | Spam precision | Spam recall | Spam F1 | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| Naive Bayes baseline | 97.76% | 99.21% | 83.89% | 90.91% | 98.11% |
| Logistic Regression final | 99.28% | 98.62% | 95.97% | 97.28% | 99.55% |

These are measurements on this single dataset split, not a guarantee of performance on current messages. The full values and confusion matrix are in `reports/` and are regenerated by `python train.py`.
